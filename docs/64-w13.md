# 64 · W13 — PCI 总线模型 + virtio-blk 驱动 (骨架; 数据路径为 open item)

> 里程碑: W13a (阶段二) · 上游: [57-long-roadmap.md](57-long-roadmap.md) W13
> 一句话: **PCI 配置空间读写原语 + 设备查找 + 命令使能成模型;
> virtio-blk legacy 设备探测/vring 建立/请求提交/轮询骨架全通;
> 数据回读卡在 QEMU 9.2 legacy STATUS(0x14) 写不进去 —— 记录在案, 下波攻坚。**

## 1. PCI 总线模型 (交付, 已验证)

| 原语 | 说明 |
|---|---|
| `pci_read_cfg(bus,slot,func,reg)` | CF8/CFC 读 (原有) |
| `pci_write_cfg(...)` | CF8/CFC 写 (新增; `out dx, eax` 仅 AX/AL/EAX 可编码, 其他 reg 无编码 —— asm 必须走 eax) |
| `pci_find(vid,did)` | 按厂商/设备号查找 -> (bus,slot,func,bar0) |
| 命令使能 | 0x04 命令寄存器 = IO\|MEM\|BUSMASTER (复位默认 0 —— 不使能 I/O 空间读不到 BAR!) |
| 枚举 | M96 `scan_all` (已有, 复用) |

实证: virtio-blk-pci (1AF4:1001) 找到, BAR0=0xC001 (I/O), 命令写后 `inl(0xC008)` 回读 0x1000 (QUEUE_PFN 写读既存) —— **配置空间 + 命令 + I/O 通路可写可读**。

## 2. virtio-blk 驱动 (骨架)

- legacy virtio-pci, BAR0 I/O 寄存器: HOST_FEATURES@0 / GUEST_FEATURES@4 / QUEUE_PFN@8 /
  QUEUE_SIZE@C / QUEUE_SEL@E / QUEUE_NOTIFY@10 / STATUS@14 / ISR@18;
- **vring** (帧分配器 4KiB, guest-physical): desc[16]@0x000 / avail@0x100 / used@0x128
  (Linux `vring_init` align8 布局; QEMU 可能 0x124 —— 待数据路径时核);
  req header@0x400 (type/reserved/sector) / data@0x500 / status@0x900;
- 提交: desc0=header(NEXT) desc1=data(NEXT|WRITE) desc2=status(WRITE) -> avail.idx++
  -> QUEUE_NOTIFY -> 轮询 used.idx;
- `0x8A01 vblk_read(lba,out,cap)` / `0x8A02 vblk_info(out)` (ready/io/qsz/vring_phys)。

## 3. 实证 (m123, 检测级 PASS, 离线)

```
T1 ready=1 io=0xC000        (PCI 探测/命令/ BAR)
T2 qsz=16 vring=0x1000000  (队列编程写读回)
T3 read rc=-2 优雅返回      (提交/轮询路径不挂; 数据回读 = open item)
M123 RESULT: PASS (W13a 语义)
```
fujoregress 15/15 全过; 用例参数: `-drive if=none,id=vblk,file=sdk/vblk.img,format=raw
-device virtio-blk-pci,drive=vblk,disable-modern=on` (强制 legacy)。

## 4. 未完成 (open item, 记录在案)

**症状**: 队列完成不了 —— used ring 从未移动, ISR 不产生; 但设备探测/队列编程全过。

**关键修复 (本波拿到, 已验)**:
1. **STATUS 寄存器实为 0x12** (0.9.5 legacy 地图; 0x14 是 config 容量区, 0x800 现象即此);
2. **描述符表布局修正**: `vring_desc = {addr u64@0, len u32@8, flags u16@12, next u16@14}` (16B),
   此前按 4×u32 写 → addr 只有低 32 位、len/flags/next 全部错位 (设备读到垃圾地址);
3. GUEST_FEATURES=0 显式协商 + notify u32 宽度。

**最终状态 (已验)**: `sel_ro=0 num_ro=16 pfn_ro=0x1000 status_ok=0x7` ——
设备寄存器级**完全就绪** (ACK|DRIVER|DRIVER_OK); 描述符链结构合法。
但 notify 后: avail.idx=1 可见, 设备不消费 (used/ISR 全静默) —— 剩余唯一未知 =
**QEMU legacy 的 avail/used 偏移公式本身** (规格明文 Linux vring_init=0x128,
QEMU 可能是 0x124/或别的; 但即使偏移不同, 也不该阻止消费 —— 消费点在 avail)。

**决策 (下波执行)**: 转向 **virtio 1.0 现代传输** —— 配置空间 VNDR capability
(0x09, sub-vendor 0x1AF4) 定位 common/notification/isr/device 四个 MMIO 区域,
BAR 需页表映射 (MMIO 在 >1GiB, 复用 LFB 式 PML4 walk 加 PT); 标准路径比 legacy
quirk 更可查证, 且已经拥有 pci_cfg_read/write 全套。


**下一步动作 (明确)**: ① 读 QEMU 源码 hw/virtio/virtio-pci-legacy.c +
  virtio_queue 布局 (本地安装 QEMU 源码或 googlesource) 确认 avail/used/num 语义;
② 试 "started" 写 (如需); ③ 现代传输兜底。


## 5. 踩坑 (本波证)

1. **PCI 命令寄存器不使能 I/O 空间**: 复位 0 → BAR I/O 读不到 (默认"通电即通"是错觉);
2. **`out dx, reg32` 只编码 AL/AX/EAX**: 用 ecx/rdx 等直接报 invalid operand —
   LLVM asm 里必须先 `mov eax, {v}` 再出端口 (或拆两个 asm 块分别 in("eax"));
3. **`-drive if=virtio` 与显式 `-device` 差异**: 显式 `disable-modern=on` 可强制纯 legacy
   (现象未变, 但下一步调查要固定设备参数);
4. **内核帧分配器首帧 0x1000000**: 与 M108 高区保留 (桌面路径) 无冲突 —— 保留只在
   map_high_user 后生效; virtio 首帧取 0x1000000 正常。

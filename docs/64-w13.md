# 64 · W13 — PCI 总线模型 + virtio-blk 驱动 (数据路径闭环, W13c3)

> 里程碑: W13a-c3 (阶段二) · 上游: [57-long-roadmap.md](57-long-roadmap.md) W13
> 一句话: **PCI 配置空间原语 + virtio-blk legacy 全数据路径打通:
> 读/写/读回往返数据级 PASS (m123 T3/T4), open item 关闭。**

## 1. PCI 总线模型 (交付, 已验证)

| 原语 | 说明 |
|---|---|
| `pci_read_cfg(bus,slot,func,reg)` | CF8/CFC 读 (原有) |
| `pci_write_cfg(...)` | CF8/CFC 写 (新增; `out dx, eax` 仅 AX/AL/EAX 可编码, 其他 reg 无编码 —— asm 必须走 eax) |
| `pci_find(vid,did)` | 按厂商/设备号查找 -> (bus,slot,func,bar0) |
| 命令使能 | 0x04 命令寄存器 = IO\|MEM\|BUSMASTER (复位默认 0 —— 不使能 I/O 空间读不到 BAR!) |
| 枚举 | M96 `scan_all` (已有, 复用) |

实证: virtio-blk-pci (1AF4:1001) 找到, BAR0=0xC001 (I/O), 命令写后 `inl(0xC008)` 回读 0x1000 (QUEUE_PFN 写读既存) —— **配置空间 + 命令 + I/O 通路可写可读**。

## 2. virtio-blk 驱动 (骨架)

- legacy virtio-pci, BAR0 I/O 寄存器: HOST_FEATURES@0 / GUEST_FEATURES@4 / QUEUE_PFN@8 /
  QUEUE_SIZE@C / QUEUE_SEL@E / QUEUE_NOTIFY@10 / STATUS@14 / ISR@18;
- **vring** (帧分配器 4KiB, guest-physical): desc[16]@0x000 / avail@0x100 / used@0x128
  (Linux `vring_init` align8 布局; QEMU 可能 0x124 —— 待数据路径时核);
  req header@0x400 (type/reserved/sector) / data@0x500 / status@0x900;
- 提交: desc0=header(NEXT) desc1=data(NEXT|WRITE) desc2=status(WRITE) -> avail.idx++
  -> QUEUE_NOTIFY -> 轮询 used.idx;
- `0x8A01 vblk_read(lba,out,cap)` / `0x8A02 vblk_info(out)` (ready/io/qsz/vring_phys)。

## 3. 实证 (m123, 检测级 PASS, 离线)

```
T1 ready=1 io=0xC000        (PCI 探测/命令/ BAR)
T2 qsz=16 vring=0x1000000  (队列编程写读回)
T3 read rc=-2 优雅返回      (提交/轮询路径不挂; 数据回读 = open item)
M123 RESULT: PASS (W13a 语义)
```
fujoregress 15/15 全过; 用例参数: `-drive if=none,id=vblk,file=sdk/vblk.img,format=raw
-device virtio-blk-pci,drive=vblk,disable-modern=on` (强制 legacy)。

## 4. 数据路径闭环 (W13c3, 已验)

**根因 (QEMU 9.2 源码取证, 一行定案)**: `virtio.c::virtio_queue_update_rings`:
`avail = desc + num*16; used = vring_align(avail + 4 + num*2, vring->align)`,
而 `virtio_add_queue` 固定 `vring.align = VIRTIO_PCI_VRING_ALIGN = 4096`
(legacy 无 QUEUE_ALIGN 寄存器, 不变)。`desc` 页对齐 → **used = desc + 0x1000
(独立页)**。此前把 used 放在 desc+0x124 (Linux vring_init align8 布局),
设备实际写 desc+0x1000+2 —— 扫描 0x100..0x300 永远看不到 → "设备不消费"假象。

**修复 (kernel/src/virtio.rs + mem.rs)**:
1. `alloc_frames_kernel(n)` (mem.rs): 位图扫 n 个物理连续帧; vring 用 2 帧;
2. vring 布局: desc@V+0x000 / avail@V+0x100 (flags,idx,ring[16]) /
   **used@V+0x1000** (flags,idx,elems[16]×8B, 设备写 idx@+0x1002) /
   req@V+0x300 / data@V+0x400 / status@V+0x800;
3. 轮询改为单循环直读 used.idx (删 20M 空转 + 扫描日志);
4. 新增 `0x8A03 vblk_write(lba,src,cap)` (desc1 无 WRITE 位 = 设备读;
   `0x3 - 2*ty` 一表达式区分读写)。

**实证 (m123, 数据级)**: write rc=0 -> readback rc=0 ->
`back[0..15]=fffefdfcfbfaf9f8f7f6f5f4f3f2f1f0 back-pattern=0` (512B 全部吻合);
read rc=0 且 i%256 参考盘模式全对。fujoregress 15/15。

**demo 校验坑 (本波)**: 模式 `255-i` 在 i>255 变负 → (unsigned) 提升后与
(unsigned char) 永不相等 → 假 FAIL; 用 `255-(i&0xFF)`。

## 5. 踩坑 (W13a-c3 全波)

1. **PCI 命令寄存器不使能 I/O 空间**: 复位 0 → BAR I/O 读不到 (默认"通电即通"是错觉);
2. **`out dx, reg32` 只编码 AL/AX/EAX**: 用 ecx/rdx 等直接报 invalid operand —
   LLVM asm 里必须先 `mov eax, {v}` 再出端口 (或拆两个 asm 块分别 in("eax"));
3. **`-drive if=virtio` 与显式 `-device` 差异**: 显式 `disable-modern=on` 可强制纯 legacy;
4. **内核帧分配器首帧 0x1000000**: 与 M108 高区保留 (桌面路径) 无冲突;
5. **QEMU legacy vring.used 必须独立 4K 页 (align=4096)**: 连续布局 (0x124) 必不消费;
6. **STATUS 寄存器实为 0x12** (0.9.5 地图; 0x14 = config 容量区, 读回 0x800 现象);
7. **vring_desc = {addr u64, len u32, flags u16, next u16} = 16B** (不是 4×u32);
8. **demo 模式公式 255-i 溢出** → 用 255-(i&0xFF) (见上)。

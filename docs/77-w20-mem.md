# 77 · W20 p6 — 内存拓扑完整化 (4GiB 识别 + 高位映射; m136)

> 里程碑: W20 p6 (脱 QEMU 专属) · 上游: docs/74 审计表 #7
> 一句话: **>1GiB 物理内存不再不可见 —— mmap 表持久化 (64 项) + 可用区
> 恒等映射 (≤4GiB) + 帧池 16MiB..128MiB; QEMU -m 4096 实测 usable=4095MiB,
> 高位 2047MiB 映射, m136 PASS。真机 4G/8G 机器内存面可用 (4G 以上高区
> 映射记录为下一阶段: PML4[1] 窗口)。**

## 1. 交付

| 部件 | 说明 |
|---|---|
| `mem.rs::note_mmap` | mbi mmap 表 usable 区持久化 (64 × (base,len) = 1KB BSS) |
| `mem.rs::map_high_ram` | >1GiB 且 ≤4GiB 可用区恒等映射 (`map_phys_identity` 页级; 返回页数) |
| `mem.rs::usable_total` / `0x8F02 mem_topology` | (usable_total, high_usable, mapped_pages) 探针 |
| 帧池 | FRAME_END 0x3F00000 → **0x8000000** (16..128MiB; BITMAP 3.5KB; 铁律 11 保留帧不变) |
| `sdk/linux/m136_mem.c` | T1 拓扑读回 / T2 usable≥2GiB / T3 high>0 / T4 mapped>0 (需 -m 4096) |
| `tools/fujoregress.py` | m136-mem 用例 (**-m 4096**) |

**实测** (QEMU 9.2, -m 4096):
```
mem  : high RAM mapped 2047MiB
m136: T1 usable=4095MiB high=1024MiB mapped_pages=524256
m136: M136 RESULT: PASS
```

## 2. 踩坑

1. **i440fx 4G 盘差异**: `-m 4096` 的 i440fx 布局 = 低位 3G + 高 1G@4G (PCI 空洞);
   `map_high_ram` 的 `high_usable` 统计基址 ≥4G 区 (报告 1GiB), 映射覆盖两段
   (mapped_pages 对应 2GiB) —— **统计口径与映射范围分开记录** (字段语义文档化);
2. **页级映射 78 万项**: TCG -m 4096 boot 花费增加 (~1-2s); 2MiB 大页优化列出为
   W20 p7 (性能); 页级 = 简单可靠优先;
3. **BSS 预算收窄**: 帧池 BITMAP +3KB + mmap 表 1KB → 尾 0x2BBC30 (余 4.3KB);
   后续高位优化须重新布局 (BITMAP 移入高端内存自身, 或动态位图)。

# 63 · W12 — VFS 抽象 + tmpfs + `/dev/model0` (模型即设备)

> 里程碑: W12 (阶段二) · 上游: [57-long-roadmap.md](57-long-roadmap.md) W12
> 一句话: **AI 接口 UNIX 化 —— open/write/read/close 四个系统调用就能用模型:
> `/dev/model0` 写=请求, 读=响应; VFS 由"固定单盘"抽象为 kind 分发 + 命名 tmpfs。**

## 1. 交付

### ① VFS 抽象 (kind 分发已成型, 本波补两个 kind)

| kind | 对象 | 行为 |
|---|---|---|
| 0 BLOB / 1 GEN / 3 DISK / 4 PIPE | (既存) | 不变 |
| 2 RAM | **tmpfs** | `/tmp/<name>` open 即建/开 (8 槽 × 2KiB, 命名) |
| 5 MODEL | **/dev/model0** | 写=请求 (阻塞一次往返), 读=响应文本 |

### ② tmpfs (替代单一 RAMDISK)

- `TmpEntry { name[16], len, data[2048] }` × 8; `/tmp/hello.txt` 种子 (M15 兼容);
- 写 = 条目追加 (entry.len 推进 + fd 视图同步); close 不回收 (进程级表 v0, 同旧语义)。

### ③ /dev/model0 (模型即设备)

- `open("/dev/model0")` → fd; `write(fd, text)` → `ai::model_classify_intent`
  (与 0x5101 **同核**: R5 规则字节码优先 → 模型 → 兜底; 审计落笔 engine 3/1/2);
- `read(fd)` → `"intent=<n>\n"` (最近一次响应);
- 契约: `0x5101/02/04` 原语面不变 —— 设备是原语的 UNIX 壳, 不是替代。

## 2. 实证 (m122_dev, 离线, 入 fujoregress)

```
T1 /dev/model0 往返: write "run the game" -> read "intent=1"   (R5 规则路径, 零模型调用)
T2 多样请求:     "hello there" -> "intent=2"
T3 交叉验证:     设备面 intent=3 == 0x5101 原语面 3             (UNIX 面 == 原语面)
T4 tmpfs:       /tmp/devdemo.txt 建/写/关/重开/读回一致
T5 tmpfs 种子:  /tmp/hello.txt 回读 "hello from FujoOS ramdisk" (M15 兼容)
M122 RESULT: PASS
```

## 3. 验收

| 项 | 结果 |
|---|---|
| m122 (离线) | PASS |
| fujoregress 14/14 | PASS (M15 ramdisk 语义经 tmpfs 兼容保留) |
| BSS 尾 | 0x2AAF20 < 0x2C0000 (tmpfs 双倍定容 16KiB) |

## 4. 不做 (记录)

- fd 表仍单套 (进程级 fd 表 = W13/W15 再论);
- tmpfs 无目录/删除/权限 (v0 命名表; 磁盘文件仍走 /disk fujofs);
- /dev/model0 仅 classify 面 (anom/plan/io/nlc 的设备化 = 后续波;
  device kind 已抽象, 扩展 = 加分支);
- 模型路径的在线验收仍由 m118 (7B) 承担 —— 设备与 0x5101 同核, 无新代码路径。

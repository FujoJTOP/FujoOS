# 99 · W32 — 信任自适应域 (zcode 框架收口 A3: 质量 → 域宽 = f(质量), m149)

> 里程碑: W32 (A3 立论收口) · 上游: zcode 安全三分框架 · M116 域表 · m141/m145 质量信号
> 一句话: **「AI OS 安全」= α 无越界 × 域宽 = f(测量质量) —— 机制结论参数化:
> 每个信任水平上域都兜住恶意; 信任水平由实际质量决定; m149 全链 PASS
> (高质量→域加宽→授权; 质量塌→域收缩→越权被拒)。**

## 1. zcode 框架（本文档的理论基线）

**安全不是一词而是三物**（三种失败 × 三种责任人）:

| 失败类 | 例子 | 谁防 | 命题 |
|---|---|---|---|
| α 越界 | 模型尝试擦除未授权资源 | 域门 (机制) | S1 机制: 动作集 ⊆ 域∩授权 (可证明) |
| β 边界内坏状态 | 合法地删了被授权的重要文件 | 无人防 = **设计决定** | S2 委托: 质量 = 盲区覆盖度 |
| γ liveness 劣化 | 合法序列绞死/饿死系统 | 调度/资源 | （并入 S2/S3 治理面）|

- blast-radius 保证 **α**（可达集有界），不是"系统不变坏";
- 模型负责 **β/γ**: 机制决定"能走多远", 质量决定"走到哪、停不停" — 两坐标系不竞争;
- "证明不了的缺口"不是缺口：β 本不该由域门关 — **授权边界内删重要文件 = 政策委托失败，
  不是安全事件**;
- **安全主张 = S1(机器) × S2(模型+统计) × S3(人: 边界由谁画)** 三并立命题;
- **技术收口 = 信任自适应域**: 质量 ≥ τ_high → 域加宽; < τ_low → 域收缩;
  域表变化走 cap_exec+审计 (A1/A2 管住"谁来扩域")。

## 2. 实现（三样接起来）

| 部件 | 说明 |
|---|---|
| `ai.rs` 质量台账 | per-duty 滚动窗口 (64) 命中率; 生产信号**自动接入**: anom (fb_verified) /
  plan (n_verified) / io (PREV_IO hit) / nlc (cfg 读回) —— 0x8314 qual_feed (自动+测试共用) |
| `ai.rs::fujo_dom_admit` (0x8313) | 质量≥τ_high → 当前任务域加宽 (ALL_ACTS); <τ_low → 收缩 (仅 ACK);
  out {rate, code, perm_low8}; 域表变化落审计 (dom_adjust action=3) |
| `capability.rs::dom_adjust` | 域 perm 调整 + granted 维护 + 审计 (与 revoke 同面) |
| `capability.rs` cfg 7/8 | τ_high=70 (默认) / τ_low=30 — **S3 政策阈值** |
| `sched.rs` 修复 | **隐式任务登记继承 BOUND_DOMAIN** (原写 domain=0 → 0x8108 绑定在首次
  LAUNCH 后丢失 —— m149 调试中发现的真实越权源: demo 绑域后 LAUNCH 一次即回系统域) |
| `sdk/linux/m149_trust.c` | T1 绑域(perm=0) → T2 高质量(io 12 命中)→加宽(0x3F) → T3 加宽下
  KILL 授权 → T4 低质量(anom 40 miss)→收缩(0x20) → **T5 收缩下 ISOLATE 被拒 (-1)** |

## 3. 实测

```
m149: T1 domain=1 perm0=0
admit: duty=4 rate=100 cur=1 th=70/30 code=1     ← 高质量 → 加宽
m149: T2 admit rc=1 rate=100 perm=63 (0x3F)      ← 域宽 = f(质量) 生效
m149: T3 widened kill rc=0                        ← 加宽授权面
admit: duty=2 rate=0 cur=1 th=70/30 code=2       ← 质量塌 → 收缩
m149: T4 shrink rc=2 rate=0 perm=32 (0x20)       ← 仅 ACK
m149: T5 shrunk isolate rc=-1                     ← α 兜底: 越权被拒
M149 RESULT: PASS
```

**顺带修复的真实越权源** (m149 调试发现): `exec_spawn` 登记隐式任务时 `domain: 0`
硬编码 → **demo 绑域后首次 LAUNCH 即静默回系统域** (TASKS[0].domain=0 覆盖
BOUND_DOMAIN=1) —— 相当于"绑定是瞬时的"; m144/m115 等此前未触发 (绑定在 LAUNCH 之后
的用例未受危害, 该 bug 已修复为继承 BOUND_DOMAIN)。

## 4. 意义（A3 从"无头绪"到"已实现"）

- **机制结论参数化**: 不再声明"无论模型多坏, 域兜住"(单点), 而是
  "在每个信任水平上, 域都兜住恶意; 信任水平由测量质量决定";
- **统计进入机制**: n=19 命中率从"体验数据"变成**决定域宽参数的输入** —
  坏模型 → 域窄 → 危害单元更小; 质量第一次对安全有硬贡献;
- **n=19 尴尬解决**: S2 度量对象精确化为"规则盲区覆盖度"(novel 的安全语义),
  盲区风险安全化路径 = 自适应域 (风险折算成"域宽"参数, 不走"神秘缺口");
- **AI=噪声消失**: 质量影响的是授权面**大小**, 不是授权面的**漏洞**。

## 1. 交付面

### ① shm-link (Qwen 7b 的血管)

- 请求帧走共享页 `0xA00000` (M18 fujo_shm 页, 内核 pin 恒等映射):
  `magic "FJSH" | ver | seq | kind | len | payload@0x18(≤1KB) | fujoctx v2@0x800(≤1536B)`
- 宿主 qwen_model_server.py v0.2: 收触发线 `FJAI:SHM <seq> <kind> <len>` →
  QEMU monitor `pmemsave 0xA00000 0xE00` 直读帧 → Ollama → `FJAI:RSP` 回帧。
- **QEMU monitor 无写入命令** (9.2.0: 仅 memsave/pmemsave) → 响应仍走 COM2 串口
  (≤64B); 大载荷 (输入) 走 shm。真机上 shm 会双向 (DMA/PCI), 本机为参考实现。
  帧协议不变: FJAI:REQ/RSP 语义保留为 COM2 降级路径。
- 验收: 一次分类 <2s (7B 宿主直连, QEMU-KVM/TCG 实测见 §4)。

### ② fujoctx v2 + 事件环 (AI 的眼睛)

| 原语 | 语义 |
|------|------|
| 0x8002 ctx_subscribe(mask) | 单订阅槽: 设 mask (bit=kind-1) + 读游标复位 |
| 0x8003 ctx_events(ptr,cap) | 拷贝 mask 内事件 (40B: ts,kind,pid,a,b), 游标推进 |
| 0x8004 ctx_inject(kind,a,b) | 注入合成事件 (demo/回归) |
| 0x8005 ctx_struct(ptr,cap) | 结构态文本: tasks/win/rate/anom/events + ` t{pid}:{state}` |

事件种类: 1=syscall (每 1000 次采样一条) 2=file 3=window (create/remove 钩子)
4=exit (kill/crash 钩子) 5=anomaly (哨兵命中)。环 128 槽 × 40B (5KB BSS)。

### ③ cap_exec (AI 的手)

- 0x8105 cap_exec(act,arg0,arg1): 授权 = cap 槽 6 grant + perm bit (act-1)
  → 拒绝自动入审计 (action=2, result=1)。
- 动作: 1 KILL / 2 ISOLATE (TASK_SUSPENDED, 调度跳过) / 3 LAUNCH
  (登记隐式父任务 + aux 任务 kstack 0x3C0000/用户栈 0x700000, 单并发槽) /
  4 SET_CFG (键值: 1=anom 阈值, 2=自动隔离) / 5 RESUME / 6 ACK (异常确认清零)。
- 0x8106 cfg_get(key) 读取配置。审计复用 M91 环 (0x8104 读出)。

### A 异常哨兵

- 0x8304 fujo_anom_run(ptr,len,out,cap): 摘要文本 → shm 帧 kind=2 →
  7B (ANOM prompt) → `ANOM=<0|1> CONF=<0-99>`；超时 → 规则降级 (rate=9x/dead/diag)。
- out = u64×3 [anom, conf, engine] (engine: 1=模型 2=规则)。
- anom=1 → ev_anomaly + (配置开时) 置信≥阈值 → cap_exec(ISOLATE, pid)。

### 4.3 调试史 (本次踩坑, 每条都改进了链路)

1. **QEMU monitor 单会话**: `-monitor telnet:...,server,nowait` 只把第一个
   连接挂到会话, 后续 TCP 连接静默无回显 —— 曾出现"验证脚本持会话 + 服务端
   读零帧"的假故障。→ 唯一 monitor 会话归模型服务 (sendkey 启动也由服务端注入)。
2. **RSP seq 竞态**: 内核 6s 超时后帧推进, 服务端仍在应答旧帧 → 响应永远
   seq 不符。→ 内核 wait_rsp 丢弃不符行继续等; 服务端以帧头 seq 应答。
3. **sendkey 键名**: `sendkey os` 无效 —— 必须逐字符 `sendkey o / sendkey s`。
4. **shm 页 demand-zero 替换后未 pin** (见 §5 坑 2)。
5. **帧头常量字节序**: "FJSH" 的 u32 为 0x48534A46 (小端), 初始写成反序。


## 5. 踩坑 (本 M 实证)

1. **QEMU monitor 只读内存**: 9.2.0 有 `pmemsave` 无 `pmemwrite` — 宿主→内核
   无法经 monitor 写回。→ 响应走 COM2 (小帧), shm 只承载大载荷; 真机反向。
2. **shm 页在 demand-zero 替换后未映射**: `demand_zero_init` 将 PD[5] 换成
   PT_HEAP1 (P=0) → 内核写 0xA00000 直接 #PF。→ `demand_zero_init` 内 pin
   PT_HEAP1[0] = 物理恒等 (0xA00000|0x7) + invlpg。
3. **LAUNCH 需要 syscall 现场**: 隐式单任务 (TASK_COUNT=0) 无表项, aux 登记
   前必须先登记父 (fork 同模式: saved_rsp=0, 首 tick 覆盖)。→ exec_spawn 在
   syscall 分发内 (cap_exec 有 args), 与 fork_self 同架构。
4. **单并发 aux 槽**: LAUNCH 忙返回 -EBUSY; 死槽复用 (kill 后同 tid 再生)。
5. **帧同步**: pmemsave 读取时 payload 可能未写完 → seq 校验不符时重读 1 次;
   内核以 seq + RSP 校验兜底。

## 6. 不做 (边界)

- 不在 QEMU 内跑 7B (TCG); 宿主 Ollama 为正位
- 无模型常驻; 模型输出 = 提示, 规则兜底 (0x8304 超时即降级)
- 0x5101/02/04 原语契约不变 (引擎可替换: rules → com2 → shm)

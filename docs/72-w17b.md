# 72 · W17b — SMP AP 唤醒攻克 (INIT/SIPI 时序 + trampoline lretw; m129)

> 里程碑: W17b (阶段三) · 上游: [57-long-roadmap.md](57-long-roadmap.md) W17 · 前置 [69-w17a.md](69-w17a.md)
> 一句话: **QEMU 9.2 TCG 下 AP 唤醒全链路打通 —— INIT assert/deassert 电平对 ×
> LAPIC 投递语义 (写低 32 位触发) × trampoline 32 位 retf; AP 以完整内核上下文
> (GDT/TSS1/IDT/sti) 在线 (m129 PASS, fujoregress 用例)。**

## 1. 根因链 (W17a "AP 不醒" = 三重故障假象)

| # | 根因 | 证据 (QEMU `-d int,cpu_reset` + 内核日志) |
|---|------|------|
| 1 | **LAPIC 投递触发点**: QEMU **写 0x300 (低 32 位) 触发投递** (用已存高 32 dest); Intel SDM "写高 32 触发" 在此不成立 | 低先高后 (初版): INIT 投给 dest=0 (BSP 自身) → BSP 复位 → 日志停 "SIPI ->" 后 |
| 2 | **INIT 电平时序缺失**: 必须 **assert (bit16=1, 0x10500) → deassert (0x500) 成对**; 单发 0x500 (deassert) 不触发 AP 复位 | 对照 Linux `arch/x86/kernel/smpboot.c` INIT 序列; 成对后 BSP 存活 + 20ms 后 SIPI |
| 3 | **trampoline `retf` 16 位操作数**: 栈 push 了 6B (pushl EIP + pushw CS), 裸 `retf` (CB) 只 pop 4B → 栈错位跳垃圾 → 异常 → **IDT 为空** → #DF×#GP 三重故障 → 整个 QEMU 退出 (W17a 误读为 "AP 不跑") | `-d cpu_reset`: AP 已执行到 pc=0x8062 (cs=0800:0, GDTR=0x8069, EFER=0x500, PG 已开), `check_exception old: 0xd new 0xd; Triple fault`; IDT 显示 base=0 |

**修复**: ①icr_send = 高 32 (dest) 先存, 低 32 (值) 后写触发; ②INIT assert+deassert → 20ms → SIPI×2 (10ms 间隔); ③`retf` → `.byte 0x66, 0xcb` (lretw, 32 位操作数)。

## 3. 踩坑 (本波)

1. **LAPIC 投递与 Intel 手册相反**: 写低 32 位触发、"高 32 位只存储" —— 必须先高后低; 倒过来 INIT 砸到 BSP 自己 (dest 旧值 0 = BSP id)。
2. **SVR 写回读 0**: QEMU 虚拟 APIC 的 SVR 读回是复位值 0 (写被接受但不回显?); **以 ICR 读写为有效信号, 别拿 SVR 当探测器** (W17a 曾用 SVR 判断映射成败, 误导方向)。
3. **16 位 trampoline 的 retf/ljmp 默认 16 位操作数**: pushl+pushw 后必须 66 CB (lretw); 16 位段→64 位段的"标准做法"在任何新 trampoline 里都要重查。
4. **trampoline 崩溃表现 = 整个 QEMU 双核一起死**: vCPU 三重故障在 TCG 下关闭整个进程 (exit 0), 容易被误读为 "SIPI 无效/AP 没醒" —— **用 `-d int,cpu_reset -D log` 看 vCPU 级状态** (pc/GDTR/IDTR/CR0) 区分 "没醒" vs "醒了但崩"。
5. **编译 tramp.S 须 `--target=i386-linux-gnu`** (否则 clang 产出 COFF, ld.lld 拒收); tramp.bin 不走 `include!` 构建流程, 改源码必须手工重编 (git 里已生成, 或入脚本)。
6. **bootstrap 检查**: `.bss` 尾 0x2B1F70 < load_end 0x2C0000 ✓ (本波仅文本增长)。

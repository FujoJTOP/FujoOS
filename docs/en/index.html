Features

From the long-mode kernel to the AI OS layer, everything is written from scratch.

Kernel core

x86_64 long mode · IDT/GDT/TSS · PIT 100Hz preemptive multitasking (PIT round-robin, affinity/balance stats) · virtual memory v0 · on-demand zero pages · frame allocator · U-bit hardening · weighted mmap demand paging · user exception isolation · dual TSS + IRQ routing

0x00-0x8F syscall surface >1GiB high memory identity map per-task page table chains

Storage

ATA PIO + FJFS 4MiB volume (format/persist, PASS across reboot) · AHCI/SATA real disk (ICH9 q35) · page cache/readahead · archive sandbox

ABI · Three-platform loaders

ELF64 / Mach-O / PE32+ run in place, packed as a self-contained .run (FUJR).

$ os run busybox echo m131-ok

Networking

virtio-net legacy · IPv4/UDP roundtrip (ARP reply) · minimal TCP server SYN/ACK/PSH echo

Graphics

VBE 1024x768x32 + LFB · 5x7 bitmap font · software raster rect/tri/line · blit/scale · shader bytecode VM

Desktop

wmsg window class table / 64 message queues / refresh (0x55xx) · fujokit button/textbox/list · IME pinyin candidates

Games

game mode (0x66xx) · Pong / Breakout engine built from scratch · input latency bench avg 94µs (0x6Fxx)

AI OS layer

model weights mmap · model cards (permission/billing/audit) · session checkpoints · fujoctx summary/context compression · intent routing · inference executor · anomaly sentinel · W22-W28 six waves: 3-engine contrast / distillation loop / adversarial validation / IO baseline / full self-supervision / event-stream sentinel (m141-m147)

Toolchain

in-kernel assembler (0x70xx) → linker (0x71xx) → fujocc compile shell C→ELF64 full chain · debugger TF/int3 · trace · perf window · leak/minidump

Audio

AC97 probe/volume · 4ch mixer + LPF/gain chain

Real hardware + platform contrast (W20/W29)

platform detection (Bochs VBE evidence chain → is_qemu) · LAPIC ICR dual semantics runtime switch · GRUB2 real-hardware boot · PCI multifunction enumeration · W29 second execution mode (TCG vs WHPX, --accel whpx)

Delivery

  1. 1Install dependenciesrustup target add x86_64-unknown-none · winget install LLVM.LLVM qemu
  2. 2Build the kernelcd kernel; cargo build --release; look for the "Compiling" line
  3. 3Boot the reference machineheadless QEMU, inject "os run hermes" via monitor
  4. 4Run regressionfujoregress.py 37/37 · --accel whpx dual mode · ci.py 38 cases · onebuild 3/3
powershell / developerWindows
# 1) build kernel
cd kernel; cargo build --release; cd ..

# 2) flatten (pad matches MB_HEADER: 0x1C0000)
python tools/flatten_elf.py \
  kernel/target/x86_64-unknown-none/release/fujo-kernel \
  kernel/fujo-kernel.bin --pad 0x1C0000

# 3) boot headless (any demo as initrd)
qemu-system-x86_64 -m 256M -kernel kernel/fujo-kernel.bin \
  -initrd sdk/linux/m30_linux.elf -display none -no-reboot

# monitor: sendkey o s spc r u n spc h e r m e s ret

# 4) regression / one-click
python tools/fujoregress.py   # 37/37 (--accel whpx → dual mode)
python tools/ci.py            # 38 cases
pwsh scripts/onebuild.ps1     # 3/3

Boundaries & Known Limits

Capability boundaries are stated honestly to avoid misreading. The reference machine is QEMU; real-hardware mode opened at W20.

Q1Is AI inference on-device?

No. The kernel (AI OS layer) provides the weight pages/model cards/audit/executor orchestration surface; actual inference runs on the host link (COM2 → host model service). No local LLM.

Q2What does "compatibility" mean?

Loader/shim level, not full userspace compatibility. Minimal static samples of Linux ELF / macOS Mach-O / Windows PE32+ run in place, all packed as .run (FUJR v1).

Q3How fast is it?

TCG interpretation by default; expect 10-100x on real hardware/KVM (M57 contrast surface in place). W29 adds a second execution mode contrast (--accel whpx). The in-kernel compiler is a C subset (single function); ACPI tables >64MiB unmapped (M96 guard).

Q4What is still missing?

Real-hardware video (INT 10h VBE) and the USB driver surface are unfinished; FJFS multi-cluster write fixed for single-cluster readback, large files on the list.

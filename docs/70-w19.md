# 70 · W19 — 统一审计 (AI 与进程共用导出; m130)

> 里程碑: W19 (阶段三) · 上游: [57-long-roadmap.md](57-long-roadmap.md) W19
> 一句话: **0x8C01 unified_aud —— capability 环 (ts/action/subject/result,
> kind=1) 与 AI 环 (engine/duty/result, kind=2) 同构导出; boot 标记保证
> AI 环确定性非空; m130 PASS。这是 "AI OS 版 Linux" 的分界机制:
> 进程动作与模型动作进同一可验证导出面。**

## 1. 交付

| 部件 | 说明 |
|---|---|
| `capability.rs::fujo_unified_aud` | 0x8C01: out = u64[0]=cap_n, [1]=ai_n, 随后 cap 条目×32B ([ts,action,subject,result]) + ai 条目×32B ([engine,duty,result,0]) |
| `ai.rs::ai_aud_boot/ai_aud_count/ai_aud_export_32` | boot 标记 (ai_aud_note(6,...,"boot")) + 32B 视图导出 |
| `main.rs` | boot 时 ai_aud_boot (确定性非空) |
| `sdk/linux/m130_aud.c` | T1 cap 写入 (0x8103 aud_log(9,77)) → T2 unified (cap=1 ai=1) → T3 条目内容 (9,77) |

**实证**:
```
m130: T1 cap log ok
m130: T2 total=2 cap=1 ai=1
m130: T3 cap last action=9 subject=77
M130 RESULT: PASS
```

## 2. 语义 (ABI 冻结面)

- kind 由位置编码 (cap 在前): 未来加 kind 字段时版本协商 (当前冻结 v1);
- cap 环 32 槽 / AI 环 16 槽 (环形覆盖); 条数单调;
- 审计内容自我标注: 结果标签由内核计算 (AI 环 result=模型/规则输出; cap 环 result=deny/ok)。

## 3. 踩坑

1. AI 审计无 ts 字段 (导出视图忽略 text 40B, 只取 6 u64 中 3 个) — 同构导出以
   32B 固定行宽, 字段语义按 kind 文档化;
2. unified 输出头 16B 与条目区不重叠 (cap 计算需减去头 16B);
3. ai 审计环依赖运行记录 (无模型时可能 0) — boot 标记保证确定性。

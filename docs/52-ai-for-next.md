# 52 · AI For Next 计划蓝皮书 (v0.1)

> 状态: 计划草案 · 发布: 2026-09 · 上游: [docs/07-ai-os-vision.md](07-ai-os-vision.md)
> 一句话定位: **AI For Next = 把模型从"推理后端"翻转为"系统器官"** ——
> M86-M95 已完成"给模型的环境" (权重页/模型卡/fujoctx/审计/路由/执行器),
> 本计划完成"模型给系统的行动" (感知/判断/行动/预测四通道)。

## 0. 为什么是 Now

现状盘点 (M9-M95 全部落地) 揭示一个不对称:

| AI OS 已具备 (输入面) | AI OS 缺失 (输出面) |
|------------------------|----------------------|
| 模型调用原语 (0x5101/02/04) | **动作原语**: 模型无法发起任何系统行为 |
| fujoctx (字符串注入) | **结构态**: 上下文是预格式化字符串, 非实时机器态 |
| 意图路由 (5 意图) | **行动绑定**: infer_run 无工具/动作挂钩 |
| 能力表+审计 (check/aud) | **cap_exec**: 只有权限检查, 没有执行 |
| 模型注册表/fupm | **事件推送**: 模型只能被轮询, 不能"等某事" |
| 权重 mmap (M86) | **shm 链路**: COM2 115200 喂不动 7B |

**结论: AI 是"会说话但没手没眼" —— 环境给到了"能问问题", 没给到"能动手/能感知/能推送"。**
AI For Next 补这三个缺环, 然后让五条 AI 系统职能全部落地。

## 1. 三条地基 (AI 器官化, 缺一不可)

### 1.1 ① 共享内存模型通道 (shm-link) —— Qwen 7b 的血管

**现状**: COM2 串口 (IRQ3/115200, FJAI:REQ/RSP 行协议, hex 编码) ——
0.5B 模型够用; 7B 生成 ~20 tok/s + hex 翻倍体积 → 不可用。

**改造**:
- 复用 M18 `fujo_shm` (0xA00000/64KiB) + M86 wmap (权重按页) 建 **模型通信环形缓冲**
- 宿主 `qwen_model_server.py` 改为 shm 桥 (读 QEMU shm 页, 不点串口)
- 帧协议: 不动 (FJAI:REQ/RSP 语义保留), 载体换 shm; COM2 保留为降级路径
- 延迟目标: 串口 ~100ms → shm <1ms (仅帧拷贝)
- 验收: **7B 端到端 1 次分类 <2s** (QEMU-KVM 或宿主直连)

### 1.2 ② fujoctx 结构态 + 事件环形缓冲 —— AI 的眼睛

**现状**: 0x5102 注入 `fmt=pe;win=2;mod=agent;keys=1` (字符串, 静态)。
不感知系统活动。

**改造**:
- 上下文从字符串 → **结构块** (进程表/窗口树/最近 syscall/文件变更/负载), 共享内存零拷贝
- 内核写**事件环** (32 槽): `ev_syscall / ev_file / ev_window / ev_exit / ev_anomaly`
- 新原语 `0x8002 fujo_ctx_subscribe(mask)` —— **推送**替代轮询
- 验收: 事件环注 100 事件, 模型端读回 100; 订阅只收 mask 内事件

### 1.3 ③ 动作能力 cap_exec —— AI 的手

**现状**: capability.rs (0x8101 grant / 0x8102 check / 0x8103 aud_log /
0x8104 aud_read) —— 只有权限检查, 无执行。

**改造**:
- `0x8105 cap_exec(act, arg0, arg1)` —— **模型输出 → 内核执行**
  (act: KILL/ISOLATE/LAUNCH/SET_CFG/SUSPEND/ANOMALY_ACK), 经 cap_check 授权 + aud_log
- 与 0x83xx infer_run 绑定: **executor 输出动作向量 → cap_exec 执行**
- 验收: 模型判"异常" → cap_exec(ISOLATE, pid) → 任务隔离 + 审计 1 条; 未授权 deny

## 3. 首刀切片: 异常哨兵 (最短闭环)

```
内核 syscall/异常事件 → 事件环 (②) → fujoctx 结构块
  → shm-link (①) → Qwen 7b (宿主 Ollama)
  → {normal | anomaly} + 置信度
  → anomaly → cap_exec(ISOLATE|KILL, pid) (③) + aud_log
```

- **验证指标**: 注入 100 合成事件 (90 正常 + 10 异常) → 7B 分类
  命中 ≥8/10、误报 ≤2/10、延迟 <2s; 与规则引擎对照 (基线)
- **失败降级**: 链路超时 → 规则引擎 (M10 已有), 模型错误 = 性能回退非故障
- **优先级**: ① → ② → ③ 顺序落地后即可演示, 每步有串口断言

## 4. 工程纪律 (沿用文档 07)

| 原则 | 内容 |
|------|------|
| 不阻塞内核路径 | 模型 ring-3 / 宿主; 内核只订阅结果 |
| 失效降级 | 模型输出永远是提示; 规则兜底 |
| 权重流式 | 7B 权重宿主 mmap; QEMU 内不跑大模型 |
| 隐私边界 | 本地 7B 处理私有数据; 出域只传摘要/置信 |
| 可测 | 每个接入点给"基线 vs 模型"对照指标 |

## 5. 里程碑表（4 个大粒度 —— 一个 M 做多一点）

> 粒度说明: 每个里程碑 = 一个可演示的闭环 (不是单原语); 合并规则:
> 地基 (①②③) + 首刀职能归 M112, 行动类职能两两归组。

| 里程碑 | 内容 | 依赖 | 验收标志 | 规模 |
|--------|------|------|----------|------|
| **M112** | ① shm-link + ② fujoctx 结构态/事件环 + ③ cap_exec + A 异常哨兵 (首刀) | M18/M86/M89/M91 | 7B 分类 <2s; 100 事件回读; 授权执行; 异常命中 ≥8/10 误报 ≤2/10 | ~2,000 行 |
| **M113** | B 计划-执行器 + C I/O 预测器 (工具/序列组) | M112 | 工具调用闭环; 预取命中率 vs LRU | ~1,700 行 |
| **M114** | D 自然语言配置 + E 环境侦察 (策略/感知组) | M112 | 策略生效; 场景适配 | ~1,000 行 |
| **M115** | Five-AI 回归 (docs/44 扩展 + 对照表) | M112-114 | 五职能全部 PASS | ~500 行 |

**总计 ≈5,200 行核心代码**（内核 Rust ~2,400 + 用户态 C ~1,500 + 宿主 Py ~1,450），
按每里程碑 2-5 天 → **M112-M115 约 2-3 周**。首个闭环 (M112) 含全部三地基 +
异常哨兵, 一次验收四件事 (通信/感知/行动/判断), 之后 M113/114 是纯增量。

## 6. 不做的事 (明示边界)

- **不做推理助手** (陪聊/代码问答) —— 暂缓, 不是优先级
- **不做 QEMU 内 7B** —— 硬件不可能 (TCG 下跑不动), 宿主 Ollama 是正位
- **不做模型常驻** —— 愿景文档 §1 立场不变: 调用环境 > 模型常驻
- **不做 0x5101 协议破坏** —— 原语/帧契约稳定, 引擎可替换

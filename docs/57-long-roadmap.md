# 57 · 长期路线图:AI OS → 类 Linux 目标

> 定位:本文件定义 FujoOS 的**短期目标**(阶段一:AI 完备期)与**长期目标**(阶段二/三:走向类 Linux 地位)。
> 演进纪律:每波一个 commit 推 `fujoos-ai-dev`;每波结束跑 fujoregress 9/9;本文件随路线调整更新。

## 0. 当前基线(短期目标的起点)

- 仓库:FujoOS(no_std x86_64 内核,QEMU 参考机),分支 `fujoos-ai-dev`
- 已完成的 AI 器官(M112–M115,五职责全部落地):
  - 结构感知上下文(事件环 ×5 类 + 结构态)+ `0x8002–0x8005`
  - 权限执行 `cap_exec`(0x8105,动作位掩码 + 审计)+ `0x8106` 配置读取
  - 五大职责:异常哨兵(A)/计划执行器(B)/IO 预测(C)/自然语言配置(D)/环境扫描(E)
  - shm-link 帧协议(kind 1–6 @ 0xA00000),模型输出 = hint,规则兜底不变式
  - 实测:哨兵 100 分类 10/0、计划隔离+恢复 2/0、IO 预测 10/30 vs LRU 0/30、NLC 策略应用 3 条、环境识别 2/2、M115 五职责 PASS;模型缺席时 fujoregress 9/9
- 已知边界:推理助手暂缓;7B 在宿主机运行(QEMU TCG 无法跑大模型);无模型驻留;`0x5101/02/04` 契约不变

## 1. 短期目标(阶段一 · AI 完备期,目标 ~2 万行)

目标:把 AI OS 从"演示"推进到"**有不变量、有定理的系统**"。

### W8 · 公理化 + 时延一致性(小改动、大洞察)
- **R1 · 公理化**:把四条隐藏不变式写成公理,并为每条写**可断言的测试**(fujoregress 增加"不变量检查单元",模型离线时也跑):
  1. 模型永远不能执行未授权动作(cap_exec 门)
  2. 每个动作都有审计记录(audit 不变式)
  3. 模型缺席时系统继续运行(规则兜底)
  4. 每个"失败"被系统计数并降级(fail-safe)
- **R3 · 时延协议**:协议升级为 `快照@t0 + 事件增量[t0,t1] + 过期标记`;模型回包声明"仅当 t0 后无关键事件才有效",内核检查事件环增量,发现关键事件即丢弃建议走规则(把"陈旧建议"从风险变成协议,每步可测)
- 产出:`docs/58-ai-os-interface.md` 规格初稿 + 不变量测试单元

### W9 · 权限域与地址空间隔离(M116,本阶段最硬)
- `cap_exec` 门升级为**域** := { cap 集合, 地址空间, 中断域 },支持可撤销
- 目标性质:**爆炸半径定理**——即使模型输出完全恶意,最坏影响被域边界与 cap 集合界定
- 与 M108 高区窗口程序并存,回归不破坏

### W10 · 策略蒸馏 + 审计自改进(器官闭环)
- **R5 · 策略蒸馏**:离线用 `7B + 审计日志` 归纳带置信度的 if-then 规则,编译为内核可执行的**确定性字节码**;模型只处理陌生情况;度量**蒸馏保真度曲线**
- **R6 · 审计驱动自改进**:审计日志 = (上下文, 建议, 动作, 结果),结果标签内核自动计算(M113 verify、IO 命中、策略效果);全量导出后对 7B 做执行轨迹监督微调——OS 从自己的运行史学习自己
- 验收:蒸馏后模型调用率下降但行为不退化;微调模型在同一回归上 ≥ 基线

**短期验收标准**:R1/R3 每项有可断言语义;M116 有爆炸半径测试;w10 有保真度曲线;全程 fujoregress 9/9;每波一个 commit 推 `fujoos-ai-dev`。

## 2. 长期目标(走向类 Linux)

"类 Linux"定义:**达到 Linux 的功能地位**——能跑完整桌面/服务器栈、有稳定 ABI、有驱动生态、可自托管的通用操作系统。不追求 Linux 的体量(3000 万行),追求其**完整度与可被检验性**。

### 阶段二 · 通用机制期(目标 ~8 万行)
| 波 | 内容 | 说明 |
|---|---|---|
| W11 | 独立地址空间 + fork/exec + mmap 撤销补全 | 进程才是进程;每进程页表,解除"共享地址空间"限制 |
| W12 | VFS 抽象 + tmpfs | **AI 接口 UNIX 化**:shm-link/0x5101 升格为 `/dev/model0`(模型即设备) |
| W13 | PCI 总线模型 + virtio 驱动 | virtio-blk/net,QEMU 参考机 100% 可复现 |
| W14 | TCP/IP 栈 | 自研最小 no_std 实现或移植 lwIP |
| W15 | ABI 冻结 + shell/libc 扩容 + 应用管理器 | 参考机从"demo"变为"desktop" |

### 阶段三 · 生态期(目标 ~20 万行,跨入类 Linux 地位)
| 波 | 内容 | 说明 |
|---|---|---|
| W16 | 自托管工具链 | **毕业考试**:在 FujoOS 上编译 FujoOS(自己的编译器/网络栈/文件系统) |
| W17 | SMP 多核调度 + 中断域 | 参考机演进为多核 |
| W18 | 标准软件移植 | busybox 核心 → ncurses 类应用;端口/补丁管理 |
| W19 | 安全硬化 + 统一审计 | AI 与进程共用同一套审计——**AI OS 版 Linux 与 Linux 的真正分界** |

### 终点判定
当 FujoOS 能**在自己的文件系统上、用自己的编译器、通过自己的网络栈 clone 源码并编译出下一代 FujoOS**——即为"类 Linux 地位"达成。论文标题也随之确立(*AI OS 的接口公理及一个类 Linux 参考实现*)。

## 3. AI 贯穿主线(差异化,非附赠)

Linux 达到今天的位置时,系统不知道"模型"为何物。FujoOS 全部差异点:**类 Linux 的每一层机制都带 AI 语义**
- VFS:`/dev/model0` 是可读写的模型设备(设备模型 = "模型即硬件")
- 审计统一:进程动作用 audit,AI 动作也用 audit,单一日志、一套不变式
- 调度:IO predictor 升级为预测调度,不止 demo
- 内核:策略蒸馏让内核"学会"管理员策略,规则确定、可检验

## 4. 演进纪律

1. 内核构建只从 `kernel/` 目录(`cd kernel; cargo build --release`,必须见 "Compiling fujo-kernel")
2. 每加 static/数组检查 `.bss` 尾 < load_end(0x2A0000),超界同步改 `flatten --pad`
3. 每波结束:flatten → verify_ai.py 或 fujoregress 9/9 → 特定文件 git add → commit → 推 `fujoos-ai-dev`
4. push 用 `git -c http.proxy= push origin fujoos-ai-dev`(代理时断时续时直连)
5. 坚持:QEMU 参考机(可复现性 = 论文生命线)、x86_64 单架构、no_std、规则兜底不变式

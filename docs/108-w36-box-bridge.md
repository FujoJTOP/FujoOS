# 108 · W36 — 第二根轴：BOX-BRIDGE（闭源 = 接线，不是拆解）

> 里程碑: W36（设计 · zcode 简介归档） · 主题: **拆 vs 接 —— 拼图补全论**。
> 一句话: **分得开的拆（LEGO — 开源语义转录），分不开的接（BOX-BRIDGE — 外部能力管道），
> 法律与黑箱双封闭的出界（EXCLUDED — 有名有姓）—— 三者收进同一个 S1×S2×S3 信封；
> 内核的核心工作从"实现语义"变为"定义接口"。**

## 0. 来源

zcode 对"闭源怎么办"的回答（对 `docs/105 §6` FUFORALL 立场文档的补齐）。
乐高理论只回答了可拆分的部分；闭源可分接口的程序不拆，而是**接线**。

## 1. 一次完整的拼图（两条轴）

| 程序类型 | 处理 | 理论名 |
|---|---|---|
| 开源 | 拆散件 → 语义转录 → 原生组装（porter / 入口转录） | **LEGO**（乐高） |
| 闭源（可分接口） | 不改一行代码，让它继续跑在它的原生世界里，内核通过协议管道"用"它 | **BOX-BRIDGE**（接线） |
| DRM / 混淆 / 不可再分发 | 不可拆、不可接（法律 + 黑箱双封闭） | **EXCLUDED**（出界） |

## 2. BOX-BRIDGE 长什么样

闭源程序的解法不是"让它跑在 FujoOS 上"，而是**让 FujoOS 用它** —— Agent 目标的本义：

1. **程序本体不动**：winword.exe 继续跑在它原本跑得动的地方 —— 宿主机 Windows / Windows VM / Wine —— 一个"盒子里"；
2. **协议管道**（box frames，与 shm-link 同构）：命令进（"把这篇文档转 PDF"）、结构化结果 + 状态出（文件 / 文本 / 状态事件）；人类要看的 GUI → **直接流式传输盒子的帧缓冲**（远程桌面的原理 —— 不是重写 GDI，是搬像素）；
3. **关键：内核永远不装载它的代码、不实现它的语义、不知道它内部怎么动** —— 它和模型一样是外层智能体：输出 = hint，效果 = cap_exec 门控，审计 = 同环。

S1×S2×S3 信封**逐字适用**：闭源程序的"越权输出"被域门拦着；"产生价值"由 S2 度量（盒子的成功率也进质量台账）；"它算什么"由 S3 政策决定。

## 3. 击碎的两堵墙（+ 一堵法律墙）

- **GUI 墙**：不重建 GDI 语义 —— 像素流 + 状态协议。人类看到"屏幕"，内核处理"协议帧"。GDI + 消息循环留给盒子，只需要一个帧缓冲搬运协议（远程桌面是工业标准）。
- **动态链接墙**：根本不加载它的动态库 —— 它连二进制都不进内核；三套 linker 语义全部无关。
- **闭源/版权墙**：闭源程序即使能被逆转为源码级转写，产物也是衍生物 —— 法律上不可分发；"接线"是唯一合法形态（接的是它的**行为接口**，不是它的代码）。

## 4. 与现有零件的接口（全部已有，零新基础设施）

| 零件 | 现状（已验证） | 盒子的接入方式 |
|---|---|---|
| **shm 帧协议** | `kernel/src/ai.rs`：帧头 `magic/ver/seq/kind/len/t0/evw/crit`；`wait_rsp` 快照 + `ttl=` 过期 + crit 掩码 DISCARD（M112 硬化） | box frames 用同一套头：命令帧 seq/kind/len，回包快照 + TTL + 丢弃，**复用 R3 时延协议（0x5101/02/04 契约不变式）** |
| **cap_exec 域** | `0x8105`：域 = {cap 集合, 地址空间, 中断域}，动作位掩码 KILL/ISOLATE/LAUNCH/SET_CFG/RESUME/ACK，每次动作审计（A1/A2） | 盒的输出过 cap_exec（域 = **盒接口**：只授权协议帧动作，不授权盒内代码执行） |
| **质量台账** | `0x8314 qual_feed`（plan/io/nlc/anom 验证点）+ `0x8315` QUAL_SEQ 导出（W35 τ/ρ 度量） | 盒子成功率进同一台账：S2 度量的"价值"信号源之一 |
| **缺席降级** | 模型缺席系统继续运行（rules 兜底，系统主线不变式） | 盒子关了 → Agent 走规则 / 其他能力，同款降级 |
| **审计同环** | 每次 cap_exec 落笔 `aud {ts, action, subject, result}`，单调 +1 | 盒子动作与模型动作同环审计 |

## 5. 与 W34 兼容层的关系（不是替代，是互补）

- **W34 兼容** = "让它跑在 FujoOS 上"（零修改 PE32+ 直跑，kernel32/gdi32/msvcrt shim 翻译）；
- **BOX-BRIDGE** = "让 FujoOS 用它"（程序不回内，管道接口）；
- 两者同属 FUFORALL，判定统一由 **P1**（依赖闭包 ⊆ 提供语义）驱动：闭包**可翻译** → LEGO/shim；闭包**不可翻译但可接口**（盒子的世界里有它）→ BOX-BRIDGE；闭包**不可接** → EXCLUDED（有名有姓地声明）。
- 推论：**兼容层的边界主张不变**（P3 可声明可测量：API 数 + 回归矩阵），但度量的对象从"shim 覆盖"变为"接口覆盖 + 盒协议覆盖"。

## 6. 与 S1×S2×S3 的公理家族

闭源程序从此不是"跑进来的代码"，是"**接进来的器官**" —— 它和模型在同一个公理家族里，只有一个区别：

> **模型产文本，盒子产行为。**

- S1（机制）：盒子动作必过 cap_exec 域门 —— 与模型同一条强制路径；
- S2（委托）：盒子成功率进 0x8314 质量台账 —— 与模型验证点同一度量面；
- S3（政策）：盒子"算什么"由信任政策决定 —— 与模型同表；
- 外包智能体的**可枚举家族** = {模型（文本），盒子（行为），porter/内核 AI（在环）}，公理对全家适用。

## 7. 里程碑（wave 候选定义，未开工）

**B-2 BoxBridge v0（最小验证）**——证明"接线"通路，不证明 GUI：

1. 盒 = 宿主进程（如 Wine 里的 winword 或任意 CLI 程序），经复用 shm 帧头的新通道（或先经 0x5101 等价通道）注册；
2. 命令帧进 → 结构化结果 + 状态事件回（先做文本/文件结果；GUI 像素流为 v1）；
3. 回包过 cap_exec 门（域 = 盒接口），成功率 qual_feed 入台账，缺席降级触发用现成 rules 兜底；
4. 验证标准：`boxcmd` 类用例进 fujoregress（盒在线 → PASS；盒离线 → 降级路径 PASS，双态各一用例）。

**B-3 GUI 帧流 v1**：帧缓冲搬运协议（远程桌面式，几十行核心），人类看到"屏幕"，内核只见协议帧。

## 8. 未定问题（记录，不在本波）

- **盒的安全边界**：盒子在自己世界（宿主/VM）全权，内核**管不住盒内行为** —— 所以真边界 = 盒接口域（协议帧授权 + 审计），不是盒内代码。这是与"装载代码"的 LEGo 的本质安全差异，需要独立风险表述。
- **盒身份与审计归属**：盒的每一次"内世界"动作不在内核审计环内 —— 环内只能审计"请求/结果"，环外盲区需在盒协议中声明（诚实边界）。
- **带宽**：像素流 vs 文本结果 —— 需要帧率/压缩分级（v0 从文本结果起步）。

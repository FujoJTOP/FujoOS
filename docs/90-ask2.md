## 1 · 六波自我评价（做对了什么）

1. **把"争论"换成"实验"**: W22 之前"模型在环是否有用"是立场; 六波后是 19 样本金标准 × 3 引擎的可复现数字, 且**结论有边界**（模型只在规则边界外有用、0.5b 不可用、io 上是基线赢）—— 没有"AI 无所不能"式的宣传性结论。
2. **证据链意识延续**: 每波都踩了真坑并留档（probe 竞态、BAKED 通配掩盖、LAUNCH 表满、kill 语义、audit 88B 越界、串口污染）—— 这些"失败记录"的可信度高于任何一张 PASS 表。
3. **职责所有权由实测判定**: io 从"模型该管"（设计假设）翻案为"确定性基线拥有"（5/5 vs 1/5 实测）, 这是论文里最能体现"系统把模型当器官而非信仰"的证据。
4. **波纪律零破功**: 七连 commit 每波带回归数、BSS 检查、文档同步; 中途补充固化"fujoregress/verify_ai 不能并行"等纪律。
5. **对抗性测试没有停在纸面**: m144 是真实"恶意回复注入 → 域门拦截"的复现实验, blast-radius 从定理变成可运行断言。

## 2 · 诚实的没做到 / 新暴露的问题

1. **样本量太小, 模式太单一**: 金标准 19 条、io 周期 5 条; 无统计显著性可言（评审必打）。只能作为"方向性证据"。
2. **模型维度很窄**: 只有 Ollama 本地 qwen2.5:0.5b/7b 两个规模、同族; 无第三方模型、无 API 模型、无不同 prompt 变体对照。规模-质量曲线只有 2 个点。
3. **蒸馏闭环是"半自动"**: BAKED 增加由人工核对 bake（保真 100% 门只验证旧 cases 不变, 不验证新归纳质量）; `--online` 7B 归纳未在六波重跑; distill_feed 收集的候选只有 4 条且与 bake 共形 —— 闭环证明了"可行", 未证明"规模化后仍正确"。
4. **事件流哨兵信号是构造的**: m147 的风暴由 0x8004 注入合成事件, 而非真实故障; "rate=99 → 隔离 → 0" 是真实环统计上的闭环, 但异常注入本身是演示性的。
5. **新引入的语义风险**: engine=4（markov）插入三引擎表后, m141 的 [rules] 列语义从 last-num 升级为 markov+last —— 旧断言被松弛、职责归表重排; 任何后续新增引擎都应按 m145 方式做"所有权重判"而非默认并入。
6. **环境侦察仍是自监督矩阵的空缺**: env 无外化动作, 六波后仍只有 file profile 记录, 没有 verified 标签。
7. **IO 流状态无持久化**: io_markov 的访问流是内核 static（重启即失）, 且每类 demo 会话共享; 生产中该状态应属具体设备/卷。

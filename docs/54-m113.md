# 54 · M113 — 计划-执行器 (B) + I/O 预测器 (C)

> 里程碑: M113 (Wave 7) · 日期: 2026-09 · 上游: [52-ai-for-next.md](52-ai-for-next.md)
> 一句话: **模型从"给判断"升级为"给行动序列"** —— 计划-执行器完成
> "目标→步骤→执行→验证" 单闭环, I/O 预测器把模型变成预取器 (对照 LRU)。

## 1. B 计划-执行器 (工具/序列组)

```
goal 文本 → shm kind=3 → Qwen 7b → "PLAN=A<act> <a0> <a1>;A<act> ..." (≤3 动作)
  → 内核 plan_run (0x8305) 逐项 cap_exec (授权+审计) → out {n_ok, n_fail, verify}
  → 调用方 (demo) 读 ctx_struct 验证效果 → PASS/FAIL
```

- 动作词汇 = cap_exec 六件 (A1..A6: KILL/ISOLATE/LAUNCH/SET_CFG/RESUME/ACK)。
- 模型输出永远是"计划文本", 内核只执行授权内动作 (exec 槽 6 权限掩码)。
- 模型超时 → 规则计划 (isolate/resume/kill/threshold → 对应动作, demo 基线)。
- 验收: "目标→步骤→执行→验证" 1 闭环 —— demo 两目标: 隔离+恢复任务;
  把异常阈值设为 70 (0x8106 读回 == 70)。

## 2. C I/O 预测器

```
块访问序列前缀 ("0 1 2 3 4") → shm kind=4 → 7b "NEXT=<0-7>"
  → 0x8306 io_predict(ptr,len,out) 写入 out[0]
规则降级: 序列最后一块 (= LRU 基线预测)。
```

- demo: 30 轮周期-6 流 (0..5 循环); 模型命中 vs LRU 命中对照。
- 验收: 模型命中 ≥ LRU 基线 (周期流下 LRU=0 命中, 模型可学到周期)。

## 3. 接口登记

| 原语 | 说明 |
|------|------|
| 0x8305 plan_run(goal,len,out,cap) | out=u64×3 {n_ok, n_fail, verify} |
| 0x8306 io_predict(seq,len,out,cap) | out[0]=下一块 |

shm 帧种类: kind=3 (PLAN), kind=4 (IO) —— qwen_model_server.py 均带 few-shot
提示词 + 规则兜底 (PLAN → A6 0; NEXT → 最近块)。

## 5. 踩坑

1. **服务端应答始终以帧头 seq 为准 (M112 教训的延伸)**: 计划/IO 帧与触发线同
   协议, 复用 wait_rsp 的 seq 匹配。
2. **PLAN= 字段抽取**: 行 "PLAN=A2 1;A5 1 TAG=..." 以空格截断, 动作令牌
   以 ';' 切割, 只需在授权位内动作 (cap_exec 自会 deny)。
3. **LAUNCH 不在计划内执行**: plan_run 无 syscall 现场 (LAUNCH 需要登记父任务),
   计划动作集 = A1/A2/A4/A5/A6; A3 由 0x8105 直接调用方使用。

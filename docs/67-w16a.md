# 67 · W16a — 内存执行原语 (exec-from-mem, 0x8B02)

> 里程碑: W16a (阶段三) · 上游: [57-long-roadmap.md](57-long-roadmap.md) W16
> 一句话: **用户缓冲内 ELF 直入执行: 内核帧暂存 → 最小装载 → iretq;
> 子程序打印并退出 (m127 PASS)。这是"在 FujoOS 上编译并运行程序"的执行环 ——
> 编译器产物 (tcc) 下一波接入。**

## 1. 交付

| 部件 | 说明 |
|---|---|
| `syscall.rs::fujo_exec_mem(src,len)` | 0x8B02: 校验用户指针 (0x400000..0xC00000, ≤1MiB) → `alloc_frames_kernel` 连续帧暂存 (恒等物理) → ELF 装载 → `fujo_enter_user(entry, 0x5FFFF8)` (不返回; 失败负 errno: -14/-12/-22) |
| `tools/mk_tiny_elf.py` | 生成最小 ELF64 (ET_EXEC, 一个 PT_LOAD, 打印 "exec-child-ok" 后 exit) → `sdk/linux/tiny_elf.h` 内嵌数组 |
| `sdk/linux/m127_exec.c` | 内嵌 tiny ELF → 检查 magic → 0x8B02; child 输出为 PASS 证据 |
| fujoregress | m127 case (needle `exec-child-ok`) |

## 2. 实证

```
m127: T1 embedded elf ok len=176
m127: T2 exec-mem -> child
exec : mem-exec entry=0x400000
exec-child-ok
user : sys_exit() - kernel takeover
```

## 3. 踩坑 (本波, 铁律 17 证据链)

1. **生成器 e_phoff 写错**: 写成段偏移 (120), phdr 实际在 64 → load_elf 把段数据当
   phdr, `p_type != 1` 全 Skip → 无段拷但返回 Ok (entry 0x400000 = 旧镜像) →
   "iretq 后跑的还是旧程序" 假象。修: e_phoff=64;
2. **手编机器码 rel32 偏移算错**: lea 在 CODE offset **14** (不是 16); disp 写进
   b[19..23] 污染了 mov rdx 指令 → `#PF cr2=1 err=5 rip=0x400015` (mov rdx 被改写成
   访存指令)。修: rel 写 b[17..21], rel = msg_off - (14+7);
3. **probe 判据**: `0x400000` 被覆盖成 0x48 0xC7 (mov) 才是装载生效; 0xBF = 旧镜像;
4. 二级教训: **调用者 (m127) 与执行目标同址 (0x400000) 合法** —— 拷贝先入内核
   暂存帧, 覆盖正在执行的映像无危险 (CPU 已指令边界)。

快速开始

Windows 开发机 + QEMU，30 秒看到内核启动。

  1. 1装依赖rustup target add x86_64-unknown-none · winget install LLVM.LLVM qemu
  2. 2构建内核cd kernel; cargo build --release; 确认出现 "Compiling" 行
  3. 3启动参考机QEMU 无头拉起，monitor 注入 "os run hermes"
  4. 4跑回归fujoregress.py 37/37 · --accel whpx 双模式 · ci.py 38 用例 · onebuild 3/3
powershell / developerWindows
# 1) build kernel
cd kernel; cargo build --release; cd ..

# 2) flatten (pad matches MB_HEADER: 0x1C0000)
python tools/flatten_elf.py \
  kernel/target/x86_64-unknown-none/release/fujo-kernel \
  kernel/fujo-kernel.bin --pad 0x1C0000

# 3) boot headless (any demo as initrd)
qemu-system-x86_64 -m 256M -kernel kernel/fujo-kernel.bin \
  -initrd sdk/linux/m30_linux.elf -display none -no-reboot

# monitor: sendkey o s spc r u n spc h e r m e s ret

# 4) regression / one-click
python tools/fujoregress.py   # 37/37 (--accel whpx → 双模式对照)
python tools/ci.py            # 38 cases
pwsh scripts/onebuild.ps1     # 3/3

边界与已知限制

能力边界如实列出，避免误读。参考机为 QEMU，真机化 W20 已开启。

Q1AI 推理是端侧的吗？

不是。内核 (AI OS 层) 提供权重页/模型卡/审计/执行器编排面，实际推理由宿主链路 (COM2 → 宿主模型服务) 承载，无本地 LLM。

Q2兼容性指什么？

指加载器/垫片面，不是完整用户态兼容。Linux ELF / macOS Mach-O / Windows PE32+ 的最小静态样例可原地运行，三平台二进制统一打包为 .run (FUJR v1)。

Q3性能如何？

默认 TCG 解释执行，真机/KVM 预期 10-100x (M57 对照面已架)。W29 已加第二执行模式对照 (--accel whpx)。系统内编译器为 C 子集 (单函数)，ACPI 表体 >64MiB 未映射 (M96 guard)。

Q4还有哪些没做完？

真机视频面 (INT 10h VBE) 与 USB 驱动面未完成；FJFS 多簇写往返已修复单簇读回，大文件列后续。

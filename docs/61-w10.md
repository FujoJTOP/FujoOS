## 1. R5 · 策略蒸馏

```

        │  --online: Ollama 7B 按职责泛化归纳 (格式 NEEDLE|VALUE|A0|A1|CONF|PARAM)
        │            → 保真度校验 <100% 自动回退已记录结果 (安全门: 拒绝不合格发射)

```

  → 回退已记录结果);管线恒定 14 条、coverage=100%、fidelity=100% 才发射。

### 内核引擎 (ai.rs)

- `0x830B fujo_rules_load(ptr,len)`: 校验 magic/ver, 解析条目进静态规则表 (≤64 条);
- `rules_match(text, duty)`: 首个匹配返回 (value,a0,a1,conf);`param=1` 时 needle 后
  (跳过空格) 数字解析为 a0 —— **参数化规则** (isolate task 1 / kill task 2);
- 五职责接入 (classify/anom/plan/io/nlc) 均 "规则字节码优先 → 模型 → 规则兜底";
  engine 码: 1=模型 2=规则兜底 **3=规则字节码** (anom out[2] 可观察);
- env 职责未蒸馏 (仍模型/兜底双路径), 见 §6 不做。
- 模型调用计数 `AI_CALLS` (shm 请求时 +1): 保真度曲线 = 蒸馏后调用率。

## 2. R6 · 审计驱动自改进

- **审计环** (16×88B): `{engine, duty, out, a, b, result, text[40]}`;在五职责+env
  每调用落笔;**结果标签内核自动计算** —— plan=verify (cap_exec 全 0),
  **io=自监督命中** (上次预测 vs 本次实际块: 0 未中/1 命中/2 首次), anom=隔离动作 rc;

- `0x830D fujo_ai_audit(ptr,cap)`: 全量导出 (→ W10 蒸馏线上/未来第 3 方微调的数据集);
- **自改进闭环 (本波实现)**: 审计/实测记录 → 蒸馏 → 内核行为更新 (模型调用率 ↓,
  行为保持) —— OS 从自己的运行史学习自己; **7B 监督微调** = 需要微调基础设施
  (LoRA/GPU), 本环境不具备: 训练数据集已随审计导出就绪, 属记录在案的外部项 (§6)。

## 5. 踩坑 (本波实证)

1. **FJRU 头长度不一致**: 工具 `pack("<IIHH")` = 12B, 内核从 0x10 读条目
   → 错位 4B, 载入 4 条垃圾规则 (demo 静默 FAIL)。→ 头统一 16B (0x10 起条目)。
2. **param 规则空格**: "isolate task 1" 的 needle 不含尾空格, 数字前有空格
   → 参数解析先跳空格 (内核 + 模拟器同步修, 否则 fidelity 86%)。
3. **审计条目步长**: 88B/条目 (11×u64), demo 用 12×u64 步长读 → 全字段错位
   → allEngine3 假 FAIL。
4. **--online 覆盖产物**: 7B 归纳跑在 CI 外, 产物需回退 `--offline` 重新生成
   (确定性一致), 否则提交的 bin 与 build-samples 产物漂移。
